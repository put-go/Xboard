## 部署注意

- 代码合并不等于生产环境已升级。本次未连接或修改生产数据库、容器。
- 应先确认本仓库 GitHub Actions 已构建并发布包含合并提交的镜像，再拉取部署。直接构建时 Dockerfile 默认克隆 `put-go/Xboard` 的 `master`。
- 旧 Compose 使用 `web/horizon/ws-server` 多服务，默认新模板使用单个 `xboard`；现有部署文件不会因示例模板更新而自动迁移。应保留实际部署的 `.env`、数据库和 Redis 数据卷，再按所选模板适配服务名和挂载。
- 新版需执行数据库迁移，包括订单字段 `refund_amount` 改为 `surplus_credit`、邮箱规范化及历史节点/用户数据补齐。邮箱规范化发现重复身份时会停止，需要先处理冲突账号。
- 入口脚本会尝试执行 `xboard:update`，但失败后仍可能启动服务；部署时需要检查迁移输出和启动日志。不要仅以容器处于运行状态判断升级成功。
